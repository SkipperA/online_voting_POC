Anonymous Authenticated Ballot System

A demonstration of the design in Proposal for a Secure, Private, and Coercion-Resistant Online Voting System. Seven origins, one process — for now.

This is a demonstration, not an election The voters are fictional and every key in this repository is published on purpose. Several parts of the design are substituted or absent here, and each is labelled where it occurs rather than only in a document. Read docs/Demo_Scope_Limits.md before drawing conclusions from a run.

The fingerprint is of k_p^(R), the key every token must verify under. The setup console shows the same value. Two surfaces, two glances: the voting application must not learn which key to trust from the office whose signatures it checks.

Origins

A browser origin is scheme, host and port, so separate ports make these genuinely separate — separate script contexts, separate fetch policies, no shared cookies. Five are trust domains; the other two are not.

OriginServes

A run, in order

  1. Setup console — enrol voters. Phase A: what is authored before the poll opens. The poll runs with this origin stopped.
  2. Voter application — generates an ad-hoc key pair, blinds its public half, saves token-request.json.
  3. Wallet — load that file, check it against the configuration, consent. The wallet signs hash([id, c]) and transmits [id, c, s] to the office itself. Nothing comes back through the voting application.
  4. Voter application — collects the reply by presenting c, unblinds, verifies, marks a ballot and casts it.
  5. Checker — the checks of §3.7, from an origin the voting application does not control.
